# 局域网持久配对

状态：P1 产品约束。当前原型已有 TLS 1.3 双向证书、Keystore 身份和双方校验码确认代码，见 [ADR 0002](Decisions/0002-Prototype1.md)。本页的备份迁移、细分授权等长期设计不代表首版已完成；设备配对/重连及安全负向实验 pending。

## 身份与授权

- 每台安装实例建立长期密钥身份；设备 ID 与公钥绑定规则待协议设计，不使用 IP、设备名称或硬件序列号作为认证依据。
- 保存对方身份、公钥绑定、授权范围、配对时间和撤销状态；地址、名称和发现缓存可更新。
- 私钥优先评估 Android Keystore；导出、备份、恢复和设备迁移语义必须明确。不能在日志/快捷方式中写密钥。
- 首次配对必须双方明确确认，并通过可核验通道绑定身份（二维码或短码方案待选），防止仅凭发现广播信任陌生设备。
- 长期关系默认没有需要人工周期重配的到期时间；每次会话仍应新建安全上下文。

## 状态与流程

```text
未配对 → 发现候选 → 双方确认并核验 → 已配对
已配对 → 解析当前地址 → 双向认证 → 协商能力 → 建立媒体/控制会话
已配对 → 离线 / 权限不可用 / runtime 未启动 → 保留关系并报告原因
已配对 → 主动撤销 → 拒绝旧身份授权；再次连接须重新配对
```

发现可优先评估 mDNS/NSD，具体实现待选；广播仅提供候选地址，不能授予信任。发现失败时允许探索手动地址入口，但仍必须认证。网络终结点、设备重启后的可发现性与后台限制一起验证。

## 会话安全约束

采用成熟认证加密协议/库，评估双向 TLS 等方案，禁止自行设计加密算法。要求双向身份验证、会话新鲜性、抗重放、身份绑定、版本协商及降级拒绝。视频、控制、设备元数据均须在认证授权边界内，媒体子连接绑定已认证会话。

授权至少区分查看设备信息、镜像、输入控制、启动应用；首轮 UI 可简化，但 runtime 必须执行授权校验。远程包名只能作为结构化参数，不能拼接成任意 shell 命令。

主动解除配对立即中止本机会话并拒绝旧授权；对端离线时不能承诺同步删除对方记录，本地撤销应立即生效。私钥丢失或设备重装产生新身份时，旧设备记录不得自动信任同名新设备。

## 与 ADB / 特权的关系

产品配对独立于 ADB 授权与无线调试配对。P1 必须在 runtime 已激活的前提下验证日常连接不依赖 ADB；同时分别记录重启、Shizuku 停止、Root 不可用之后是否需要重新激活权限。重新激活特权不应要求重新配对 ConnectorX。

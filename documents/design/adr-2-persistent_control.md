# ADR 0002：持久身份与局域网屏幕控制原型

## 状态

已接受

## 背景

本记录保留当时的产品决策原文，当前规格见[架构](architecture-android.md)及[交互](principle-interaction.md)。

## 决策

- 日期：2026-09-07
- 状态：代码已实现，设备交互验收 pending
- 范围：双端持久配对与局域网屏幕控制；用户随后限定本轮只安装，由用户操作。

### 决策

1. 固定官方 server Java/AIDL 源码导入 `upstream/scrcpy`，以 Android library 编入 APK，保留上游包名及许可证。
2. Shizuku UserService 创建独立 app_process，避免 server 的 System.exit 与 Looper 全局初始化影响 APK。当前两台设备已有 shell Shizuku 服务，不代表新 runtime 已实测。
3. 网络终结点在 APK：TCP 45873、TLS 1.3 双向证书。Keystore P-256 私钥不导出，SHA-256 证书指纹作为身份；私有 SharedPreferences 保存对端指纹、名称和地址，禁用备份。
4. 新配对需主动开放两分钟入口，双方核对由两个证书身份派生的 96-bit 校验码并确认。非配对窗口拒绝未知证书，镜像入口另行检查持久授权。未完成独立安全审计。
5. NSD 只发现地址；IP、名称和广播 ID 不建立信任。连接仍匹配保存的完整指纹；发现失败可手动填 IP。
6. server Unix 反向连接仅连 APK，并检查本地 UID。视频经 TLS 输出，客户端按 4.1 codec/session/frame 格式解码；控制只允许键盘/文本/触摸白名单。
7. 单个被控会话；断开尝试释放已知触点并回收子进程；本地撤销立即关闭相关连接，不能删除离线对端记录。
8. 原型使用 MiuixDemo 页面结构与组件，保留本机系统栏。虚拟显示单应用和物理屏幕几何留给后续原型。

### 边界

清数据/重装会失去身份。Shizuku 激活与配对独立；当前没有 Root 直接启动、开机自启或无人值守保障。首次配对最终写入时若断线，可能只一端保存成功；重新开放入口并核对双方身份可修复，不能静默信任同名设备。

本轮构建、静态检查和安装与设备验收分开记录。UI、双端 TLS、编码和输入效果由用户操作验证。

当前来源管理已改为根目录 scrcpy/ Git Submodule；上文导入路径仅记录原型决策当时的布局。

## 后果

仅在上列状态和当前规格适用范围内继续执行，不把历史实验、提议或构建证据扩展为当前端到端能力。

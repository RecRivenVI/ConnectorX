# 原型路线与验收

0.3.8 新增验收与证据见 [布局与触摸](AppLayoutTouch.md)。本机触摸分发测试与完整远控实机验收分开记录。

2026-09-07 用户确认原型 1 画面、操控与多指触摸工作良好，记录为核心体验用户验收 PASS。下方未单独验证的完整权限/重启/安全矩阵仍 pending；音频保持后续范围。原型 2 已进入同一 APK 的交付，设备验收由用户操作。见 [原型 1](Prototype1.md)、[原型 2](Prototype2.md)。执行顺序 P0 → P1 → P2 → P3。

后续用户确认原型 2 整体符合预期，系统栏覆盖策略保留待定。原型 3 开始按只读取得的设备几何开发，详见 [原型 3](Prototype3.md)；单项刷新率/旋转矩阵不因“整体符合预期”而自动全部勾选。

状态：pending 未验证；PASS 在记录范围通过；degraded 部分能力或精度降级；FAIL 不满足；deferred 明确延期。每项记录对应需求 ID、源码基线、设备/系统、步骤、实际结果及证据路径，使用 [模板](../Research/EvidenceTemplate.md)。

## P0：权限与官方源码研究

- [ ] 固定官方源码并追踪客户端 push、通道建立、app_process、server 入口、清理链路。
- [ ] 按输入/捕获/显示/应用启动填写 ADB shell、Shizuku、Root、普通 APK 的权限矩阵。
- [ ] 记录 UID、SELinux 域、hidden API 调用、失败信息与 ROM 差异。
- [ ] 对重启、进程被杀、授权撤销的恢复行为建立实验。
- [ ] 决定 runtime 启动适配、IPC、生命周期与网络终结点，写新决策记录。

通过条件：权限结论有源码和实机证据；不能仅以普通 APK 设计进入底层能力实现。

## P1：持久配对（R01、R02）

- [ ] 两台 Android 设备发现、双方首次确认、长期身份与授权落盘。
- [ ] 重开应用、换 IP、局域网断开后重新连接，无需再次人工配对。
- [ ] 每次双向认证并加密；未知身份、伪造发现、重放、旧授权均被拒绝。
- [ ] Shizuku 与 Root 路径分别启动 scrcpy 派生 runtime，记录每条路径能力。
- [ ] runtime 激活后关闭日常 ADB 连接流程，仍能建立 ConnectorX 会话。
- [ ] 设备重启、runtime 被杀、Shizuku 停止分别验证；权限失效保留配对并提示恢复。
- [ ] 解除配对立即拒绝旧连接；离线对端、清数据/重装身份变化有明确行为。

通过条件：真实双设备完成重复连接与负向认证实验。若某启动路径未通过，标为 degraded/FAIL；不能宣称 Shizuku 与 Root 均完成。持久配对不等于重启后自动恢复特权。

## P2：指定远程应用（R03—R07）

- [ ] 查询远程已安装 App，按包名在目标虚拟 Display 启动/恢复。
- [ ] 虚拟 Display 按控制端分辨率/density 协商，记录实际应用布局及编码尺寸。
- [ ] 请求与实际 Display 刷新率、编码 FPS、呈现 FPS 分别测量。
- [ ] 画面与多指触摸/键盘可用，记录端到端延迟的测量方法与分布；验收阈值待首测后确定。
- [ ] 本机返回映射、对话框返回、本机 Home/手势退出有可重复结果。
- [ ] 远端系统栏不出现在应用画面内；当前独立应用模式真实 VD 与画面限制在本机系统栏以内，栏区域纯黑；远端 Insets 代理与全屏跟随暂停。
- [ ] 旋转验证远端 Display/Activity 状态、锁方向应用及触摸坐标；不可行时保留证据和结论。
- [ ] 桌面快捷方式直达设备 + 包名；离线/卸载/权限失效能恢复或明确报错。
- [ ] 断连释放触点，重连不补发旧事件，虚拟显示释放/恢复策略有实测结果。

通过条件：真实双设备录屏/状态与输入证据；尺寸、刷新率、旋转分别报告。旋转首轮必须完成可行性验证，负面结论可完成研究，但不能宣称功能通过。

## P3：实体设备镜像（R08—R11）

- [ ] 完整被控画面按真实比例居中，测量上下约 1.5S 留白与宽屏约束。
- [ ] 获取系统 rounded corner、DisplayCutout / overlay 元数据并记录来源与坐标。
- [ ] 不依赖人工机型库，验证圆角、刘海/水滴、挖孔路径的可用性及精度。
- [ ] 视频与几何共用变换，旋转前后裁切和输入位置一致。
- [ ] 灰色外框直线内缘无侵占/空隙；圆角外/刘海裁切，孔洞黑色无描边。
- [ ] 数据不足明确标记降级，不把 bounding rect 或半径近似标为真实曲线。

通过条件：以设备实测元数据和可复核对照图核验，不仅凭模拟器矩形截图。覆盖不同形状需相应真机；无设备样本的形状保留 pending。
